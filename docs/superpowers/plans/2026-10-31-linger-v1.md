# Linger v1 Implementation Plan

**Status:** Implemented ([PR #1](https://github.com/michaelrigart/linger/pull/1)). All
tasks are complete, including acceptance; do not run this plan again. Progress was tracked
outside this file, so the step checkboxes below stay unticked.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Linger, a sandboxed macOS menu bar app. While the user is away it posts a
zero-distance mouse event about once a minute, so the chat app keeps showing the user as available. Around dusk and
dawn it steps aside so macOS Auto appearance can switch.

**Architecture:** The behaviour lives in a pure Swift package, `LingerCore`, with no
AppKit. It holds the sun maths, the time-zone coordinates, the settings and pause rules,
the switch schedule, an `ActivityEngine` state machine driven by snapshot inputs, and the
panel copy. A thin SwiftUI app target, `Linger`, polls the system every 5 s through
small platform adapters, feeds a snapshot to the engine, posts when told to, and
renders the panel and Settings.

**Tech Stack:** Swift 6, SwiftUI `MenuBarExtra`, CoreGraphics (`CGEvent`,
`CGEventSource`, `CGSession`), ServiceManagement (`SMAppService`), `os.Logger`, Swift
Testing. XcodeGen, pinned in `mise.toml`, generates the Xcode project.

**Spec:** `docs/superpowers/specs/2026-10-30-linger-design.md`. Read it before any task.
The Evidence section explains every unusual choice below.

## Global Constraints

- Deployment target macOS 26.0. Swift 6 language mode. `MenuBarExtra` in `.window` style.
  `LSUIElement` = YES (no Dock icon).
- App Sandbox and Hardened Runtime on. The only entitlement is
  `com.apple.security.app-sandbox`. Public API only, and no network calls of any kind.
- Bundle identifier `com.michaelrigart.linger`. Ad-hoc signed (`CODE_SIGN_IDENTITY "-"`):
  no signing identity is set up yet.
- Linger posts only a zero-distance `mouseMoved` event at the cursor's current position,
  via `CGEventPost(.cghidEventTap)`: no keyboard, click or scroll events. The only
  permission it needs is Accessibility (post-event access).
- Linger never posts while it is off, paused, stepping aside, the screen is locked, the
  Mac or display is asleep, the session is not on the console, or post-event access is
  missing.
- Idle delay choices 30, 60, 120, 180 s (default 60). Post interval 60 s. Presence
  tolerance 0.25 s. Gap budget choices 300, 600, 900, 1800 s (default 900). Thresholds:
  Dark is due at a sun altitude ≤ −5°, Light at ≥ −1° (geometric altitude, no
  refraction). "Today" pauses until the next local midnight. Poll every 5 s with 1 s
  tolerance.
- Copy never claims to know the chat app's status. English only.
- Logging goes through `Logger(subsystem: "com.michaelrigart.linger", category: …)` and
  logs no personal data.
- **Build and test outside the Claude sandbox.** In the sandbox, SwiftPM's nested
  `sandbox-exec`, the clang module cache in `/var/folders`, and the build service are
  all denied. Prefix every Swift or Xcode command with
  `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` unless `xcode-select -p`
  already points at Xcode, and don't change the global selection.
- `Linger.xcodeproj/`, `build/` and `.build/` are generated and never committed.

## Review Focus

1. **A DST day** (2027-03-28, Europe/Brussels): the next step-aside time and a "Today"
   pause must land on the right local wall-clock time. Tested in Tasks 3 and 4.
2. **A time zone with no coordinates** (`UTC`, `Etc/GMT+1`): Linger never steps aside and
   never crashes, and Settings shows "Location unknown". Tested in Tasks 2, 5 and 7.
3. **Appearance switched from Auto to Light, or handling turned off, mid step-aside:**
   stepping aside ends and posting resumes on that tick. Tested in Task 5.
4. **Accessibility revoked while running:** the status becomes `needsPermission` and
   nothing is posted. When access is granted again, Linger becomes active without a
   relaunch. Tested in Tasks 5 and 6.
5. **Lock or sleep in the middle of an absence, then return:** the absence state is
   cleared, so a stale last-post time can't make Linger think the user is away (or
   back). Tested in Task 5.

- [ ] **Step 4: Implement the platform adapters and `Probe.swift`**

The probe is `#if DEBUG` only, and starts when the app launches with `-LingerProbe YES`.

At launch it logs one line each, via `Log.probe` with `privacy: .public` on these
values:
- `PostAccess.isGranted`;
- `IdleSource.seconds()`;
- `AppearanceSource.isAuto`;
- `AppearanceSource.effective`;
- `SessionState().isInhibited`.

It then loops every `-LingerProbeInterval` seconds (default 60). Each iteration:
1. Log the idle time.
2. If access is granted, read the cursor location and sleep `-LingerProbeDelay`
   seconds (default 0).
3. Post the event at the location read in step 2.
4. Log the idle time 0.5 s later.

The probe exits after `-LingerProbeSeconds` seconds (default 0, meaning never).

### Task 4: Switch schedule

**Depends on:** Task 2

**Files:**
- Create: `Packages/LingerCore/Sources/LingerCore/SwitchSchedule.swift`

**Interfaces:**
- Consumes: `SolarCalculator`, `Coordinates`, `Appearance`.
- Produces: `public enum SwitchSchedule`:
  - `static let darkThreshold = -5.0` and `static let lightThreshold = -1.0`.
  - `static func dueSwitch(at date: Date, coordinates: Coordinates, timeZone: TimeZone, effective: Appearance) -> Appearance?`
    - The expected appearance is Light when the altitude is ≥ −1, Dark when it is ≤ −5,
      and nothing in between.
    - It returns the expected appearance when that differs from `effective`.
    - It returns nil when `altitudeRange` for the day doesn't reach both thresholds
      (upper bound < −1 or lower bound > −5).
  - `static func nextStepAside(after date: Date, coordinates: Coordinates, timeZone: TimeZone, effective: Appearance) -> (target: Appearance, at: Date)?`
    - When `effective` is Light, it returns the next crossing of −5 going down, targeting
      Dark.
    - When `effective` is Dark, it returns the next crossing of −1 going up, targeting
      Light.
    - It returns `(target, date)` itself if a switch is already due, and nil on a polar
      day.

```swift
    public init()
    public mutating func tick(_ input: EngineInput, settings: LingerSettings) -> EngineOutput
    public func isUserAway(idle: TimeInterval, uptime: TimeInterval, idleDelay: TimeInterval) -> Bool
    /// Re-reads idle and uptime, posts only if the user is still away, and records the post only if `post()` returned true.
    @discardableResult
    public mutating func postIfStillAway(idleDelay: TimeInterval,
                                         reread: () -> (idle: TimeInterval, uptime: TimeInterval),
                                         post: () -> Bool) -> Bool
    mutating func didPost(atUptime uptime: TimeInterval)   // internal; tests reach it through @testable
}
```
Every public struct the app constructs has an explicit `public init`. Swift's
synthesized memberwise initializer is internal, so it isn't enough.

The rules below are what the tests pin. Apply them in this order on every tick.
1. **Status precedence:** no access → `needsPermission`; not on → `off`; paused →
   `paused(until:)`. In any of these, and also while `isInhibited`:
   - clear the absence state: last post, stepping aside, and "attempted this absence";
   - set `shouldPost` to false;
   - clear `activeSince`, except when inhibited, which keeps it so the panel still says
     "Since …".

   While inhibited (with access, on and not paused), the status is
   `active(since: activeSince ?? now)`.
2. **Presence:** `isUserAway` returns `idle >= idleDelay` when nothing has been posted this
   absence. Otherwise it returns `idle >= (uptime − lastPostUptime) − presenceTolerance`.
   When the user isn't away, clear the absence state and return
   `active(since: activeSince ?? now)` without posting.
3. **Stepping aside:** it ends when one of these holds:
   - the effective appearance equals the target;
   - Appearance isn't Auto;
   - handling is off;
   - `uptime − start ≥ gapBudget`, which also sets "attempted this absence".

   On ending, `shouldPost` is true on that same tick. Otherwise it returns
   `steppingAside(target)` with no post.
4. **Entering stepping aside:** when the user is away and all of these hold:
   - nothing has been attempted this absence;
   - handling is on;
   - Appearance is Auto;
   - coordinates exist;
   - `SwitchSchedule.dueSwitch` returns a target.

   Linger then enters stepping aside with start = `uptime`, and doesn't post.
5. **Posting:** otherwise, while the user is away, `shouldPost` is true when there has
   been no post this absence, or when `uptime − lastPostUptime ≥ postInterval`. The
   status is `active(since:)`.
